# cc-connect-observer

cc-connect 的「群聊被动参与」插件（独立仓库、独立配置、独立测试）。

## 架构（决策层）

cc-connect 托管所有 codex 会话（同一群共享同一线程，高优回合与普通回合都走它，天然连续）。
本插件只做决策：

- 每条群消息是否转交、转交的提示词内容；
- 转交时用的推理强度（高优回合 `at_effort=medium`，普通回合 `proactive_effort=low`）；
- 是否暴露思考过程（群聊回合一律隐藏思考/进度）。

## 工作方式

- 每群维护内存滚动观察缓冲（可丢，重启即清空），记录所有群消息文本；
- @ 或明确叫昵称（如“小鲸鱼”）的消息：视为高优回合，总是转交（medium 强度）；
  @ 提示词要求积极回应；叫昵称时要求结合上下文判断是否真是直接跟机器人说话，
  若只是提到/转述则回落到普通回合的“前 X% 值得回复”判断；
- 其余消息：全部先入 pending 队列；轮到处理时若整批值得参与（engage 窗口开启或
  至少一条命中激活规则，且通过频控），**把排队中未处理的全部消息合并成一次普通回合**
  （low 强度、隐藏思考、拆条发送），让模型一次性判断哪些值得回、选择性回 N 条
  ，避免排队时一条条转交导致的延迟；普通回合按"最值得回复的前 `reply_rate`%"参与
  （@/昵称高优回合不走该阈值）；
- 提示词统一结构：身份 → `【本次要求】` → `【补充近期对话】`
  （`他人对话` + `你的近期回复` 并列，有才出现）；高优回合在
  `【补充近期对话】` 前多一个 `【最新消息】`（被 @/点名的真实触发消息）；
  普通回合在 `【补充近期对话】` 前多一个 `【待处理消息】`（排队候选，
  需判断是否回复）——候选与背景是明确的两等：候选是待判断对象，
  `他人对话` 只是背景参考，不重复、不混排；
  要求段放最前，同场景回合的身份+要求前缀完全一致，可提升前缀缓存命中率；
  公共回复要求与本次要求只在代码层区分（`writeCommonReplyRules` 统一注入），
  拼进提示词时不分开呈现，避免规则漂移导致普通回合泄漏判断过程；
- 拆条用法为公共规则：回复不同的人或不同主体时，用单独一行 `---` 分隔，每条分别
  作为独立消息发出（高优回合与普通回合均启用拆条）；消息列表带发言者 QQ 号、
  消息 id、被引用消息 id；媒体消息
  （图片/语音/文件）以类型呈现、仅作上下文，不参与回复判断；模型需要时可自行用
  OneBot v11 get_msg 查询任意消息详情（ws 地址见 cc-connect 配置，消息 id 见列表）；
- 普通回合内没有值得回的就输出 NO_REPLY；
- 未触发回合的排队消息留在队列，等待后续批次一并评估；滚动缓冲同时保留它们
  作为上下文（不重复排队）；
- 真实回复经主体的 `message.sent` 钩子回灌，用于频控与 engage 窗口（NO_REPLY 不计入）；

## 配置

部署为 `<cc-connect 配置同目录或任意路径>/observer.toml`，主体 config.toml 里：

```toml
observer = "/abs/path/to/observer.toml"
```

关键项：`at_effort` / `proactive_effort` / `suppress_group_progress`、
`window_sec`（pending 超时 / 持续投递共用）、`max_batch_msgs`、
`reply_rate`、`[[rules]]`。

## 群聊提示词

固定提示词维护在同目录的 `group_chat.json`，由 `observer.toml` 的
`group_prompt_file` 指定；相对路径按 `observer.toml` 所在目录解析。启动时将
keymap 装入内存，运行期每个群回合只查内存，不重复读取文件。

身份、at/alias/普通批次要求、公共规则 `common` 和定制规则 `extra` 通过 key
读取；消息块标题、消息行格式、`reply_rate`、昵称、消息数量、发送者、时间、
消息 id 以及最近回复记录由代码动态拼接。修改 `group_chat.json` 后执行
cc-connect 的 `/restart` 即可重新加载，无需重新编译。

占位符只替换白名单内的 `persona_name`、`persona_alias`、`reply_rate`；值为空或
占位符不在白名单时原样保留，不报错。替换仅作用于 keymap 模板，不扫描消息正文。
